# 제작 의도

**댓글을 많이 다는 자동화 도구가 아니라, 영상마다 딱 한 번, 그 영상에서만 나올 수 있는 댓글을 사람이 쓰는 속도로 다는 에이전트를 목표로 했습니다.**

---

## 1. 과제를 이렇게 이해했습니다

- 이 과제의 성과는 댓글 수가 아니라 **읽은 사람이 '운명원' 연애 사주를 보고 싶어지는 것**입니다. 그런데 광고처럼 보이는 순간 이 효과는 사라집니다. 그래서 핵심을 두 가지로 봤습니다. 첫째, 그 영상에서만 나올 수 있는 말을 할 것(맥락). 둘째, 실제 시청자처럼 들릴 것(자연스러움).
- 실제 계정으로 실제 댓글을 올리는 도구라서, **운영 안전장치도 기능의 일부**로 설계했습니다. 실수 한 번이 계정 정지나 브랜드 이미지 손상으로 이어질 수 있기 때문입니다.

## 2. 설계 결정과 이유

### ① 영상 불러오기 — "최신"이면서 "연애 고민"인 영상
- 최신순으로만 가져오면 드라마 OST, 예능, 쇼츠가 섞였습니다. 그래서 **최근 7일 안에서 관련도순으로 찾은 뒤 최신순으로 정렬**합니다.
- 아래 영상은 뺍니다.
  - **쇼츠(3분 이하):** 짚을 장면이 부족합니다.
  - **음악·스포츠·게임 카테고리:** 연애 고민과 관계없습니다.
  - **1시간이 넘는 라이브 다시보기:** 자막이 너무 길어 비용이 큽니다.
  - **타로·사주 채널:** 경쟁 업종 채널의 댓글은 삭제될 가능성이 큽니다.
- 가점 기능인 **뜨기 직전 영상**은 최근 48시간 안에 올라와 조회수가 1,000~5,000이고 시간당 150 이상인 영상입니다. 지금 댓글을 달면 위쪽에 오래 노출될 가능성이 높은 영상이라 따로 모았습니다. 과제 기준에 따라 초안까지만 만듭니다.

### ② 영상 선택 — 고민 → 장면 → 시청자 → 댓글 순서로 쓰기
- AI에게 바로 댓글을 쓰게 하면 어느 영상에나 붙일 수 있는 일반론이 나옵니다. 그래서 순서를 나눴습니다.
  1. 자막(없으면 제목·설명)과 인기 댓글을 읽고 **영상이 다루는 연애 고민을 한 줄로 정리**합니다.
  2. **자막에 실제로 나온 말이나 장면을 2~3개** 고릅니다.
  3. 이 영상을 볼 법한 **시청자 한 명**(나이대, 연애 상황)을 정합니다.
  4. 그 사람의 말투로 댓글을 씁니다.
- 대시보드에 중간 결과(영상 속 고민, 참고한 장면, 댓글 다는 시청자)를 그대로 보여줍니다. 사람이 초안이 왜 이렇게 나왔는지 보고 판단하거나 고칠 수 있게 하기 위해서입니다.
- 댓글 흐름은 **영상 속 장면에 공감 → 내 상황 한마디 → "운명원 연애사주 잘 본다던데 한번 보고 싶다"**입니다. 운명원은 '소문을 들었고 궁금하다'까지만 말합니다. 이용 후기를 지어내지 않아도 읽는 사람에게 같은 궁금증을 줄 수 있기 때문입니다.
- 인기 댓글을 함께 읽혀 그 채널 시청자들의 말투에 맞추고, 최근에 단 댓글을 함께 넘겨 표현이 반복되지 않게 합니다.
- 자막이 없는 영상은 제목·설명으로 쓰고, 화면에 "자막 없음"이라고 표시해 장면 언급이 약할 수 있음을 알려줍니다.

### ③ 검사기 — AI 결과를 코드로 한 번 더 확인
- 아래 조건을 검사합니다.
  - 40~120자
  - 운명원 언급
  - 링크·해시태그 없음
  - 지어낸 이용 후기 표현 없음
  - 이전 댓글과 너무 비슷하지 않음
- **AI가 쓴 직후**와 **게시 직전** 두 번 검사합니다. 게시 직전에 다시 보는 건 사람이 초안을 고쳤을 수 있어서입니다. AI 초안이 탈락하면 탈락 이유를 붙여 최대 두 번 다시 쓰게 합니다.
- "받았는데", "맞췄" 같은 말은 평범한 문장에도 나오므로, 운명원 바로 뒤에 올 때만 후기 표현으로 봅니다. 잘못 걸리는 경우를 줄이기 위해서입니다.

### ④ 댓글 달기 — 사람처럼, 그리고 눈에 보이게
- 크롬은 평소 쓰는 기본 프로필의 자동 제어를 막습니다. 그래서 **에이전트 전용 프로필 폴더를 지정해 여는 방식**(Playwright `launch_persistent_context`)을 썼습니다. 로그인만은 사람이 한 번 직접 합니다. 자동화된 크롬에서는 구글이 로그인을 막기 때문입니다.
- 게시 과정은 다음과 같습니다.
  1. 글자마다 60~180ms 사이의 랜덤 간격으로 **한 글자씩 입력**합니다.
  2. 입력된 글이 초안과 같은지 확인한 뒤 게시합니다.
  3. **댓글 목록에서 내 댓글을 찾아** 바로가기 링크와 화면 캡처를 남깁니다.
- 진행 상태(프로필 여는 중 → 입력 중 → 게시 완료)를 대시보드에 단계별로 보여줍니다. 실패하면 사람이 이해할 수 있는 이유와 캡처를 남깁니다. 예: 프로필 창이 이미 열려 있음, 로그인 안 됨, 채널 없음, 댓글이 꺼진 영상.
- 유튜브 화면의 요소 정보(셀렉터)는 한 곳에 모아서, 화면이 바뀌어도 그 부분만 고치면 되게 했습니다. 자동화 탐지를 피하는 우회 기술은 쓰지 않았습니다.

### ⑤ 운영 규칙 — 화면이 아니라 서버와 DB에서 강제
| 규칙 | 구현 |
|---|---|
| 영상당 댓글 1개 | 서버 검사 + DB 고유 인덱스로 이중으로 막음. 계정이 달라도 같은 영상에는 한 번만 |
| 하루 게시 상한 10개 | 한국 시간 자정 기준으로 오늘 게시 수를 셈 |
| 동시에 한 건만 | 게시 중에는 다른 요청을 거부 |
| 중복 게시 방지 | 게시 버튼은 눌렀는데 확인에 실패한 경우는 실제로 올라갔을 수 있으므로 **게시한 것으로 취급**. 재시도로 같은 댓글이 두 번 달리는 것을 막음. 서버가 게시 도중 꺼진 경우도 같음 |
| 계정 자동 배정 | 가장 오래 쉰 계정에 배정해서 한 계정에 몰리지 않게 함 |
| 기록 | 모든 시도를 영상·계정·댓글·결과·캡처와 함께 시간순으로 저장하고 표시 |

화면의 버튼 비활성화는 안내일 뿐이고, 같은 요청을 직접 보내도 서버가 거부합니다.

### ⑥ 사용성 — 처음 보는 사람도 설명 없이
- 세 칸에 번호와 한 줄 안내를 붙였습니다.
- 진행 단계는 버튼을 누르기 전부터 미리 보여줍니다.
- 버튼이 왜 눌리지 않는지 항상 문장으로 알려줍니다. 예: "이미 댓글을 단 영상이에요", "오늘 게시 상한에 도달했어요".
- 시연할 때 스크롤하지 않도록 한 화면에 다 들어오게 했습니다.
- API 키나 로그인된 프로필이 없으면 상단에 무엇을 준비해야 하는지 표시합니다.

## 3. 기술 구성

| 부분 | 선택 | 이유 |
|---|---|---|
| 대시보드 | Python FastAPI + HTML/JS | 내 컴퓨터에서 실행 (웹에 올린 페이지는 크롬 프로필을 열 수 없음) |
| 영상·댓글 정보 | YouTube Data API v3 | 공식 API |
| 자막 | youtube-transcript-api | 한국어 자동·수동 자막 |
| 댓글 작성 | Claude (claude-opus-5-5) | 한국어 구어체와 맥락 파악. 응답을 정해진 형식(JSON)으로 받아 검사기와 연결 |
| 브라우저 자동화 | Playwright + 설치된 Chrome | 프로필 폴더 지정, 사람처럼 입력 |
| 기록 | SQLite | 설치 없이 규칙을 DB 차원에서 보장 |

## 4. 한계와 다음 단계
- **유튜브 화면 변경:** 화면 구조가 바뀌면 셀렉터를 고쳐야 합니다. 실패 캡처가 남기 때문에 원인은 바로 찾을 수 있습니다.
- **새 계정의 노출:** 막 만든 계정의 댓글은 스팸 필터에 걸릴 수 있어서, 운영 전에 계정을 평범하게 써 두는 기간이 필요합니다.
- **효과 측정:** 다음 단계로는 게시한 댓글의 좋아요·답글 수를 모아, 어떤 유형의 댓글(공감형, 질문형 등)이 반응을 끄는지 비교해 프롬프트를 개선하고 싶습니다.
- **광고 표시 검토:** 실제 서비스로 운영할 때는 공정위 추천·보증 심사지침의 경제적 이해관계 표시 의무를 법무 검토하는 것이 필요하다고 봅니다.
